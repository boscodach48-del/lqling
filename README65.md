# 扫码 15 秒、手机号 3 分钟：两条登录路径各走二十遍之后，我把"该用哪条"的判断写下来了

小满做跨境客服三年，每天早上八点半打完卡，第一件事是打开网页版，把夜里攒下的一百多条客户消息过一遍。她的手机永远在包里、在充电、在隔壁工位，于是"扫码"从一个动作变成了一段流程：掏出来、解锁、进设置、翻到设备页、举起来对准屏幕、等那声提示音。有阵子她干脆把手机立在显示器边上当扫码枪用，一天三四次，屏幕都照花了。她说不是不会登，是每天重来一遍这件事让人烦。

换成手机号登录，想省掉举手机这一步。结果 +86 的短信十条里到三条，剩下七条要么等两分钟才来，要么干脆不来，验证码框空着，人只能干坐。两条路都走过，坑各踩了一半。

这篇不谈"哪个更安全"这种没答案的问题，只算账：各要多久、各自死在哪一步、什么场景必须选哪条。入口与边界判断，我对着 [Telegram 网页版中文指南](https://tlgrqo-web.com) 逐条比对过。

## 一、两条路补的东西根本不一样

扫码，是**一台已登录的设备替这台电脑签字**。网页从头到尾不碰密码，也不碰验证码，判断在你手机上完成。

手机号，是**从零开始证明"我是这个号码的主人"**。它要走一遍号码所有权验证；开过两步验证的，还要再交一次只有你自己知道的密码。

区别直接决定失败成本。扫码失败重扫一次，十几秒；手机号那条路一旦卡在"号码本身出了问题"上，比如旧号已停用、号码被运营商回收转卖，整条路就不通了，得回到还能登录的设备上改绑。

## 二、摊在表上比：时间、卡点、残留

下表按我自己的操作节奏记，不是官方参数。手机在身上的前提下，一天登三次，连着记了两周。

| 对比项 | 扫码 | 手机号 + 验证码 |
| --- | --- | --- |
| 首次耗时 | 12–20 秒，含找设置页的时间 | 40 秒–4 分钟，取决于码什么时候到 |
| 熟练后 | 8–15 秒，基本是肌肉记忆 | 仍要等，输入只占 10 秒，剩下全是等码 |
| 对手机的要求 | 必须在身边、能拍照、App 是登录状态 | 只要号码能收码，手机不在跟前也行 |
| 高频失败点 | 二维码白屏或过期、手机端被杀掉推送 | 短信不来、验证码过期、两步验证密码想不起来 |
| 网页上要输入什么 | 什么都不用输 | 号码 + 一次性验证码（+ 两步验证密码） |
| 换号或停用的影响 | 无，已登录设备照样能授权 | 直接断路，新设备进不去 |
| 共用电脑上的残留 | 一条设备会话，直到你主动退出 | 同样一条会话，过程里还留下号码痕迹 |
| 典型适用者 | 自己的电脑、手机在手 | 手机不在身边、远程桌面、手机端登不上 |

最容易被看漏的是"残留"那一行。很多人以为手机号登录"更干净"，其实两条路的落点相同：浏览器里多一条会话，账户里多一台设备。

## 三、扫码这条路的四个动作位置

1. **打开入口，等二维码稳定。** 码是动态的，几十秒自己刷新一次。它还在转、还是灰框就先别举手机——那不是码的问题，是渲染或请求没走通，重载一次比扫十次有用。
2. **手机进"设置 → 设备 → 关联桌面设备"。** 这个入口在二级菜单里，第一次找要花点时间。
3. **直接对着屏幕扫，别截图。** 部分版本支持从相册读码，但截图会留在相册里，而相册的同步与备份链路你未必都清楚。
4. **读卡片再确认。** 手机上会弹出设备型号、浏览器名和城市。机型陌生、或者你根本没做这个动作，就拒绝。城市对不上不一定是被盗——公司出口、机场 WiFi、代理线路都会让位置飘，先看是不是自己按的。

这四步熟练后能压到十秒上下。压不下去的地方通常不是手速，是第 2 步那个菜单每次都要重新找。

## 四、手机号这条路的五个动作位置

1. **在二维码下方点"使用手机号码登录"**（英文界面是 Log in by phone number）。入口字号很小，第一眼容易漏掉。
2. **填带国家码的号码**，+86 后面那个 0 要去掉：`0086 138xxxxxxxx` 要写成 `+86 138xxxxxxxx`。位数错一位，页面不提示"格式错"，只会静默失败。
3. **先去 Telegram 应用里找码，再等短信。** 页面常出现 "We've sent the code to your Telegram app"，意思是码发进了 App 里那条署名 Telegram 的服务消息。盯着短信界面等，能等到天荒地老。
4. **短信不来时用输入框下方的备选。** 验证码框下面通常有"通过短信接收"和"电话语音播报"两个切换，语音播报对 +86 号段有时比短信通。
5. **两步验证的密码单独输一次。** 开了这层的账号会在验证码之后停在 "Enter your password"。连错几次进冷却，提示 "Too many attempts. Please try again later."，冷却时间按小时算。

还有一种情况要认得出来：网页提示你回到已登录设备上点确认。走到这一步，它已经变回扫码了，只是把"扫"换成了"点"。

## 五、三个最常卡住的地方，按代价排序

**短信一直不来（几分钟到几小时）。** 先分清码发去了哪个通道：App 内消息、短信、语音。多数人卡住是因为一直在等错误的那个。确认号码格式没错、没开飞行模式、没把服务消息静音，再试语音播报。

**验证码过期（一次重来）。** 网页码和短信码都是短时效的，页面会直接给"二维码已过期，点击刷新"或"验证码已失效"。过期了重拿，别连点五六次，重复请求会被风控记一笔。

**两步验证密码忘了（一周）。** 登录页有 "Forgot password?"，点了会往绑定邮箱发重置链接；提交之后有 7 天等待期，这期间**任何新设备都登不进去**，只有原来挂着登录状态的设备能继续用。它不是"忘了就找回"的普通密码，是唯一会让你停摆一周的环节。

手机号那条路的细节，[手机号登录时的注意事项](https://tlgrqo-web.com) 按号码格式、验证码通道、安全核对分开写了。

## 六、入口与证书：两条路共用的第一道判断

不管走哪条，第一道关卡都是同一个：你打开的是不是你要打开的那个站。

点地址栏左边那个锁形图标，看证书绑定的域名和地址栏里的是不是同一个、有效期有没有过；再看页面索要什么——它只需要号码和一次性验证码，任何一步开始问密码明文、问第二层验证码、问支付信息，关掉重来。三条里有一条不对就不用继续。

第二条判断是来源：地址是自己敲的、从收藏夹点的，还是群里转来的短链。仿站不会做得粗糙，往往比原站更"规范"。[浏览器登录前检查清单](https://tlgrqo-web.com) 把这些核对点列成了可勾选的条目。

## 七、五种情况，直接给答案

1. **自己的电脑，手机就在手边，一天登好几次** → 扫码，8–15 秒，最省。
2. **手机不在同一空间、没电，或者手机端登不上** → 手机号，先确认这个号码还能收码再动手。
3. **远程桌面、云电脑、投屏或串流画面** → 手机号。二维码经画面压缩和缩放会糊，扫几次都识别不出来，这不是你手抖。
4. **借来的电脑、打印店、别人的工位** → 扫码，用完**点退出**而不是关标签页；走之前回手机"设置 → 设备"核对那台机器还在不在。
5. **号码准备换、旧号已停用** → 别指望这条路。先在还能登录的设备上改绑、补上邮箱，再谈网页登录。

算笔总账：一天登三次，扫码十五秒，手机号平均三分钟，一个月 90 次，差出一个多小时。但扫码有硬前提——手机得在身上，前提不成立时，那十五秒等于零。

## 八、两条路的岔口，其实是你手机在哪儿

扫码快，是因为它省掉了"证明我是谁"，让已有设备替你担保；手机号慢，是因为它每次都要从零验证号码所有权，时长由运营商和风控决定。

选哪条从来不是技术问题。手机在手里、机器是自己的，扫码；手机不在、画面是远程的、号码还在别人名下，手机号。真正需要多花一分钟的是入口核对，和走的时候有没有退干净——那两件事跟走哪条路无关，跟你在不在意有关。小满后来把手机固定在显示器旁边，扫码重新变回十五秒；她唯一改掉的习惯，是每天下班前点一次退出，再看一眼设备列表。
