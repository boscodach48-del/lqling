# 证书报错能不能点"继续访问"：我分了 6 种情况，只有 2 种可以先放行

上周三下午，同事小林在我旁边登网页版，页面一跳，整块变成灰白色的"您的连接不是私密连接"。他手比脑子快，鼠标已经挪到左下角"高级"上了，嘴里还在说"这就是证书过期，点继续就行"。我把他鼠标按住了——不是断定这次一定出事，而是他压根不知道自己正在放行什么。同一句"不安全"，背后可能是这台机器的时钟跑偏了十分钟，也可能是有人把整个登录页换成了自己那份，而这两件事的处理方式是相反的。

**证书报错不是"能不能过"的技术问题，是"过了之后谁在看"的判断题。** 这篇只讲这一件事：六种报错怎么归类、哪两种可以先放行、见到哪三个信号立刻掉头。

## 一、先分清：地址栏那句"不安全"和整页拦截不是一回事

很多人把两件事混成一件，于是把该警惕的当噪音、把可修好的当灾难。

地址栏左侧灰色小字"不安全"，或者展开后写着"此网站的部分内容不安全"，多数时候是**混合内容**：主文档的证书是好的，只是页面里夹了 `http://` 的图片、字体或统计脚本。按 `F12` 打开控制台，能看到 `Mixed Content` 开头的警告。这种情况不影响你登录本身，属于站点自己的配置债，看一眼就好。

整页被拦下来、必须点"高级"才能进去的，才是真的**证书校验失败**。这两者的区别，决定了你要不要动手。中文的分步核对可以对着 [Telegram 网页版中文使用指南](https://tlgroq-web.com) 上的浏览器检查条目看，它把入口、版本、权限拆成独立条目，正好和下面这张表对得上。

## 二、六种报错，哪些能给入口

浏览器把原因写得很清楚，只是藏在错误码里。把码认出来，判断就成了一半：

| 你看到的原文 | 它在说什么 | 能不能继续 | 我怎么做 |
| --- | --- | --- | --- |
| `NET::ERR_CERT_DATE_INVALID`（证书已过期或尚未生效） | 本机时间和证书有效期对不上，或者证书真的过期了 | 先修时间，修好通常自己消失 | 校准系统时间，重开页面 |
| `NET::ERR_CERT_AUTHORITY_INVALID`（证书颁发机构不受信任） | 签发者不在你的信任列表：自签证书、内网 CA、抓包工具、或中间人 | **看环境定**：自家内网设备可以，公网登录页不行 | 先看"颁发者"是谁再决定 |
| `NET::ERR_CERT_COMMON_NAME_INVALID`（证书名称不匹配） | 证书是给 A 域名签的，你在访问 B | 不行 | 多半是入口进错了，或者页面被换了 |
| `NET::ERR_CERT_REVOKED`（证书已被吊销） | 签发方主动作废了这张证书 | 不行 | 关掉，换入口重来 |
| `NET::ERR_CERT_WEAK_SIGNATURE_ALGORITHM` | 站点还在用老掉牙的签名算法 | 部分浏览器给入口，但站点本身已停止维护 | 换入口，别在上面输任何东西 |
| 只有"返回安全连接"，根本没有"继续" | 该域名在 HSTS 预加载列表里，浏览器强制禁止降级 | 技术上没入口 | 只能修根因 |

表里第五条和第六条常被误读成"浏览器抽风"。不是。第六条尤其干脆：Chrome 对进了 HSTS 列表的域名**故意不给你那个按钮**，因为这条规则写在预加载清单里，客户端拦得比人可靠。

## 三、现场三分钟，按这个顺序过六步

判断靠顺序，不靠感觉。我固定的走法是：

1. **点地址栏左侧那个图标。** 注意 Chrome 117 之后锁形图标换成了调节样式的图标，点开是"连接安全"面板，很多人还在找小锁，找不到就以为浏览器没提供信息。
2. **展开"证书（无效）"这一行**，看两栏：`颁发给` 和 `颁发者`。
3. **比对域名。** `颁发给` 必须是你正在访问的那个域名本身，不能是它的兄弟域名，更不能是某台网关或路由器的型号名。
4. **看系统时间。** Windows 在"设置 → 时间和语言 → 日期和时间"里点"立即同步"；macOS 在"系统设置 → 通用 → 日期与时间"里勾上自动设置。差几分钟就够触发 `DATE_INVALID`。
5. **回想这台机器装过什么。** Charles、Fiddler、mitmproxy、某些公司安全客户端都会在中间解密流量、换一张自签证书。这类属于"你自己造的报错"，可控。
6. **用手机流量开同一页面。** 手机正常、电脑报错，问题在这台机器（时间、根证书、代理）；两边都报错，问题在链路或站点。

走到第五步，绝大多数 `AUTHORITY_INVALID` 就有答案了。走到第六步，剩下那些说不清的也基本定性。

## 四、三个信号，见到就停

有三种情况不值得再分析，直接换设备或换网络：

- **`颁发给` 的域名和你访问的域名不一致。** 这不是配置瑕疵，这是"有人在中间"。公共 WiFi 的认证页劫持最典型：证书上的名字是某个网关厂商，页面长得却像登录页。
- **页面开始向你要本该由客户端处理的东西。** 正常的网页版登录只有两条路——扫码，或者收一条验证码。任何页面在这里多问一步账号密码、二次验证码、助记词，就地关掉。
- **证书是最近几小时刚签发、颁发者陌生，而你在这台机器上从没装过抓包工具。** 三个条件同时成立，基本可以判定为动态签发的中间人证书。

## 五、能放行的那两类，边界在哪

不是所有自签证书都可怕，有两类我确实会点"继续"：

**一、自己家里的设备管理页。** 路由器后台、NAS 面板、打印机设置页，地址是 `192.168.x.x` 这种内网地址，没有人会为它去申请公共证书。这类页面只在你家内网可达，中间人插不进来。

**二、自己搭的调试环境。** 本地起的服务、抓包工具代理下的测试页面，证书是你自己装上去的，报错是预期的。这种放行的前提是：你知道这张证书是谁生成的、它现在还在你手上。

两类之外还有一条硬边界：**只要这个页面需要你输入凭据或扫码，一律不放行。** 不管它看起来多像自家系统。

## 六、为什么"先登进去再说"是最贵的一步

这是全篇我最想让人记住的一段。

中间人替换登录页，成本低得离谱：他不需要破解任何加密，只需要让你在报错页上点一次"继续"。之后二维码是他画的，你扫的那一下，实际是在给他的会话授权。整个过程里，你的浏览器没有报警，你的手机上显示"新设备登录"，看起来和你自己正常登一次没有区别。

所以"继续访问"真正让渡的，不是一次页面加载，是**这一整段会话的可见性**。在公用电脑、酒店网络、来路不明的加速器后面，这个代价和"省下三十秒"根本不成比例。

顺带一个能救命的细节：同一张证书在两个浏览器里表现不一样，往往说明问题出在根证书存储。Chrome 和 Edge 读 Windows 的系统根证书库，Firefox 用自己那套证书库。**同一个站点 Chrome 能过、Firefox 报错**，八成是公司或学校往系统里下发过根证书——到底是方便还是监视，得你自己判断。反过来，`certmgr.msc` 里多出来的陌生根证书，就是这类问题的线索。

## 七、把判断压成四条原则

1. **看你要输入什么，不看报错有多唬人。** 只读页面和登录页，容忍度完全不同。
2. **放行一次，不放行一个域名。** 浏览器会在当前会话里记住这个例外，别顺手把它变成永久习惯。
3. **能修根因就别用例外。** 时间、证书链、代理，这三样修好之后报错自己就消失了，比每次点"继续"省事。
4. **公共设备上一次都不放行。** 没有例外。

收口就一句话：**证书报错本身不可怕，可怕的是你不知道自己在给谁开门。** 看一眼"颁发者"，对一下域名，想一下这个页面要不要输入东西——三步，十秒钟，够用了。真遇上说不清的那种，别在原地纠结，换台设备换条线路重开，比研究错误码快得多。需要更细的入口核对和登录前检查，[这边的中文说明](https://tlgroq-web.com)按模块分开写了，对着自己的现象挑一条看就行。
