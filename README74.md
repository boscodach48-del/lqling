# 网页版开会投屏被踢下线之后：3 类断连原因的定位顺序，和 6 条真正管用的保活设置

周三下午的周会，我把笔记本接上投影，网页版开着客户群，正准备把一份客户确认单截图投出去。鼠标点下去的那一秒，页面白了——不是卡，是干净利落地退回二维码登录页，头像和输入框都没了。七八个人看着投影上那个巨大的二维码，我一边说"稍等，网络有点问题"，一边在手机上翻"设备"列表，果然，"Telegram Web / Chrome / Windows"那条记录已经不在里面了。

回去之后我把半年的掉线记录对了一遍：真正因为"网络不好"的只有三成，剩下的要么是我自己在手机上把设备踢了，要么是浏览器把后台标签"优化"掉了。这三种在屏幕上长得几乎一样，处置却完全不通用——拿清缓存去治心跳断，只会把自己从登录态里彻底清出去。

文中的菜单路径和报错文案，我都在 Chrome、Edge、Safari 上逐条对过；[网页版排障的中文图文说明](https://tlgrwo-web.com) 有对应的截图版，懒得读文字可以直接照着点。

## 三种"掉线"长得像，修法根本不通用

我贴在显示器边框上的判定表就三行，开会时扫一眼就能对号入座。

| 屏幕上的样子 | 大概率是哪一类 | 30 秒内的判定动作 |
| --- | --- | --- |
| 直接跳回二维码页，没有报错，历史消息也没了 | **会话失效**：被踢、过期、站点数据被清 | 手机 Telegram → 设置 → 设备，看列表里还有没有这台浏览器 |
| 页面还在，顶部挂着"正在连接…"的黄条，输入框变灰点不动 | **心跳断了**：后台标签被休眠、系统睡眠、代理抖动 | 看这个标签在后台待了多久，超过五分钟基本就是它 |
| 消息一直转圈，转完变红色感叹号，但页面和头像全正常 | **出网链路变了**：WiFi 切热点、换节点 | 新开标签访问任意网站，能打开就是链路侧的事 |

区别就一句话：账号还在不在。第一行被请出去了，只能重扫；后两行账号一直在线，只是通道断了，刷新往往就好。

## 会话失效那次，是我自己在手机上动的手

网页版登录后，手机端"设置 → 设备"里会多一条记录，通常写着"Telegram Web"加浏览器名和系统名，后面跟大致登录地点。这条记录就是它的命根子：一旦消失，浏览器这边网络再好都会被送回二维码页，而且**没有任何提示**。没有"你已被登出"，没有错误码，就是白屏一下回到登录界面，很容易被当成断网。

我自己那次就是典型：会前一天清设备，看到一长串陌生记录顺手全踢了，其中一条就是会议室那台笔记本。

另外两个来源在浏览器这侧。**站点数据被清**：Chrome 的 设置 → 隐私和安全 → 删除浏览数据 里，"Cookie 及其他站点数据"和"缓存的图片和文件"是两个独立勾选项，只清后者不影响登录，勾错了就得重扫。**会话自然过期**：长期不用的网页版会被服务器回收，表现完全一样，也是无声回登录页。

手机设备列表是唯一判据：有记录就别重扫，重扫时核对登录地点——对不上说明别人在登你的号。

## 心跳断在后台：浏览器帮我"省"掉了这条连接

这类最高频，也最坑：它发生在你没看屏幕的时候。

网页版维持在线靠的是持续连接加定时心跳。浏览器只要认为标签"暂时没人用"，就开始动手：压低定时器频率、挂起连接。Chrome 的后台标签切走五分钟后节流明显收紧，几十秒一次的心跳被压到一分钟才跑一次，服务器等不到回应就把连接判死。你切回来看见的"正在连接…"，是它在重新握手。

Chrome 现在还多了个主动收标签的功能，路径是 **设置 → 性能 → 内存节省程序**（地址栏敲 `chrome://settings/performance` 也能到），它会把长时间不活跃的标签休眠掉，回来一看全是灰的。下方有"始终保持这些网站处于活动状态"，把站点加进去就不会被回收。Edge 的同款叫"睡眠标签页"，在 **设置 → 系统和性能 → 使用睡眠标签页节省资源**，默认三十分钟不活动就睡，例外列表在它下面。Safari 没这个开关，但对后台标签更狠，切走几分钟连接就可能被挂起，用它的把网页版单独拖成窗口放前台。

报错文案认一下能省事：新版断线时顶部写"正在连接…"或"Connecting…"，旧版显示"等待网络"（Waiting for network）配转圈图标；提示条里出现"更新 Telegram"字样则是页面在拉新版本，跟掉线无关。

## 网络切换：不是断了，是两截连接在打架

把笔记本从 WiFi 切到手机热点，或中途换节点，很容易撞上这一类。

切网的一瞬间，旧连接还没正常关闭，新出口已经建好。服务器认为"这个会话还在旧通道活着"，浏览器拿着新 IP 去握手，两边对不上，页面就在"已连接"和"正在连接"之间反复横跳，更多时候卡成灰屏。这时候连按 F5 是最糟的选择，每刷一次都重走一遍完整握手，越刷越卡。

更隐蔽的是合盖：睡眠、网卡断电，醒来后连接早没了，页面却还停在原样，打字发不出去才发现。Windows 上改掉它：**设置 → 系统 → 电源和电池 → 屏幕和睡眠**，把"接通电源时，使设备在此时间后进入睡眠状态"设为"从不"；再到控制面板 → 电源选项 → 选择关闭盖子的功能，把"合盖时"设为"不采取任何操作"。

系统时间跑偏时浏览器会报 `NET::ERR_CERT_DATE_INVALID`，页面打不开，看着像被拦，去 设置 → 时间和语言 → 自动设置时间 同步就好。

## 断了之后的四步，别跳着做

顺序不能换，换了会把可恢复的故障做成不可恢复的。

1. **先确认是不是真断**。新开标签访问个网站。能打开，说明网没问题，问题在这一页；打不开就先修网，别在浏览器里折腾。
2. **分清类别**。照上面那张表对一遍：跳回二维码页就查手机设备列表；页面在、黄条在就等它自连；页面正常但消息发不出，别再刷。
3. **按类别处置**。心跳类先等 20 到 30 秒，让它走完一轮重连；还不行按一次 `Ctrl + Shift + R` 强制刷新。链路类先把网稳住（切回原 WiFi，或等热点握手完成）再刷。会话失效没得修，重扫。
4. **验证通了没有**。别拿"看起来正常"当标准，在收藏夹（Saved Messages）给自己发一条，看到时间戳刷新才算真通。真卡死了别反复点刷新，把标签拖出来单独放一个窗口，很多时候它自己就恢复。

## 六条保活设置，投屏前十分钟过一遍

一条条加上去的，现在能连着开一整天不掉。

1. **把标签固定住**。右键标签 → 固定。固定的标签被回收的优先级明显更低，也不容易误关窗口时一起没了。
2. **加内存节省程序白名单**。就是 `chrome://settings/performance` 那个"始终保持这些网站处于活动状态"；Edge 加在睡眠标签页的例外列表里。
3. **只开一个网页版标签**。同账号两个标签时，一个刷新或重连会把另一个的会话挤掉，表现就是"偶尔莫名掉线"，极难查。要对照两个群，就在同一个标签里切。
4. **电源改成不合盖睡眠**。合盖后掉电会快一些，插着电就无所谓。
5. **会前十分钟做一次假动作**。接投影之前先给自己发一个字，确认时间戳能刷新，比会中救火便宜太多。
6. **会中不切节点**。真要换线路，等一个自然停顿：先看到时间戳刷新过（说明上一轮同步完成）再切，切完别立刻操作。

网页版这些东西，[站点上按浏览器分开写的那几节](https://tlgrwo-web.com) 讲得更细，尤其 Safari 和 Firefox 的权限项跟 Chrome 差得挺多，值得对一遍再动手改设置。

## 投屏前那十分钟，比会中那两小时值钱

掉线真正烦人的地方不是修不好，而是它总挑你不能分心的时候出现。那几秒能做的判断只有一个：账号是被请出去了，还是路断了。这一句分清楚，剩下都是照表执行。

我现在开会前的流程很短：接投影、发消息看时间戳、瞄一眼手机设备列表里那台浏览器还在不在。加起来不到一分钟，省掉的是站在投影前、对着巨大二维码解释"网络有点问题"的那两分钟。

会后也别忘收尾——公用机器上主动点退出，比事后清站点数据省心。
