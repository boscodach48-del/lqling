# 换电脑后别的网站都还登着，只有电报要重扫：一张登录状态迁移表，加 4 个能提前判断的细节

上周把办公室那台用了五年的台式机换成笔记本。开机、登 Chrome 账号、等同步转完，书签回来了、密码自动填充也回来了。淘宝、知乎、公司那个后台、甚至连三年没打开过的论坛，点进去全是在线状态。我把 web.telegram.org 敲进地址栏，页面干干净净地弹出一个二维码，等着我拿手机去扫。

同事探头看了一眼，说：你这新电脑是不是有问题，怎么别的都登着就它要扫码？

电脑没问题，问题在于我们把两件完全不同的事当成了同一件：**「网站记得我」和「这台设备被授权过」**。别的站点能跟着你走，是因为它们认密码、认浏览器同步下来的凭据；电报网页版不认这些，它认的是「这台设备」，而新电脑在它眼里是一台陌生机器。

这篇围绕登录状态怎么迁移讲：哪些动作会掉登录、为什么会掉、掉之前怎么判断、换完要补哪几步。

## 一、先拆现象：那些"还登着"的站，登的其实不是同一个东西

Chrome 账号同步的内容是有明确范围的——书签、密码、历史记录、扩展、设置、付款方式。**Cookie 不在这个范围里**，而且是浏览器厂商刻意不同步的。

原因很直白：Cookie 里装着你在每个站点的会话凭证。一旦能跨设备同步，等于任何一台登录了你 Google 账号的机器都能接管你全部网站的登录态，中间连一道确认都没有。这个口子没人敢开。

那你新电脑上那些"还登着"的站是怎么进去的？三种情况居多：

- 密码管理器自动填了一次，页面自己跳进去，你没留意中间那一下；
- 站点发了长期有效的"记住我"令牌，同时你手动输过一次密码；
- 你压根没在那台机器上退出过——两台各自独立登着，看着像"跟着过来了"。

电报网页版这三种情况都不成立。它没有"账号＋密码"这种登录方式，两步验证密码只在开启之后作为第二道门出现，主凭据永远是手机端那一下确认。**没有密码可以自动填充，也就没有"跟着过来"这回事。**

## 二、一张迁移表：什么动作会掉登录，什么动作不会

| 迁移动作 | 旧环境的会话 | 新环境要做什么 | 手机要不要在手边 |
| --- | --- | --- | --- |
| 同一浏览器开新标签页 | 保留 | 什么都不用做 | 不用 |
| 同一浏览器换配置文件（Profile） | 不共享，等于一台新设备 | 重新扫码或收验证码 | 要 |
| Chrome 换到 Edge（同一台机器） | 不共享 | 重新授权一次 | 要 |
| 台式机换笔记本 | 不共享 | 重新授权一次 | 要 |
| 只换网络、换线路 | 一般保留 | 无 | 不用 |
| 清掉 Cookie 与站点数据 | 丢失 | 重新授权一次 | 要 |
| 开无痕/隐私窗口访问 | 关窗即清 | 每次开窗都要 | 要 |
| 手机丢了或换了手机号 | 网页端可能还挂着，但确认推送没了 | 先处理账号恢复，再谈迁移 | 关键 |

表格末行需要单独说一句。很多人以为手机没了网页版还能凑合用，实际是：会话可能还在，但**任何需要手机确认的动作都做不了了**——换设备、改密码、踢掉可疑登录，全部卡死。账号恢复的优先级，永远高于"把网页版登回去"。

## 三、为什么换浏览器就等于换设备

打开手机 App，进「设置 → 设备」（部分版本叫「已连接设备」），你会看到一列条目：iPhone、Windows 桌面端、Chrome on Windows。每一条都带设备名、平台、登录 IP、最近活跃时间。

这就是关键：**电报把所有登录点都记成设备，网页版是其中一台，和你的手机平级**，不是什么"附属页面"。浏览器里那份 Cookie 存的正是这台设备的授权密钥，服务器那边有一一对应的记录。

换浏览器 = 换了一台服务器没见过的设备。它手里没有密钥，也没有任何可以自证的凭据，只能让你走一遍授权：扫码，或者手机号收码。

反过来验证这个逻辑特别简单：在手机上对着某条设备点「终止会话」，那台电脑下一秒就掉线。你删的不是"登录状态"这个抽象概念，是一条具体的设备记录，密钥跟着作废。

## 四、换新浏览器之后的五步迁移

按这个顺序做，中间不会卡。

1. **先在手机上确认 Telegram 活着**。打开 App，进「设置 → 通知」，看推送是不是被系统的省电策略掐了。手机端收不到确认，后面全白搭。
2. **地址栏手敲域名**，别点群聊里别人转的短链。判断入口真假看两处：地址栏的域名本身对不对；点左侧锁图标 → 证书，看「颁发给」里的域名和地址栏是否一致。不一致的，直接关掉。
3. **手机扫码**。网页上出现二维码，手机 App 进「设置 → 设备 → 扫描二维码」（英文界面是 Link Desktop Device）。注意方向：**是手机扫屏幕上那个码，浏览器不需要摄像头权限**——这点经常被搞反，然后跑去浏览器设置里翻摄像头开关。
4. **给设备起个能认出来的名字**。扫码成功后网页会让你命名，写「办公室-笔记本-Chrome」，别留默认的 `Chrome on Windows`。否则设备列表里躺着三条一模一样的条目，日后真出事你分不清哪条该踢。
5. **回手机上核对一遍**。刷新设备列表，确认新条目出现；顺手把已经淘汰的旧条目点开、选「终止会话」。这一步一分钟，能省掉以后所有的"这台是哪来的"。

二维码刷不出来或一直转圈的话，先开一个无痕窗口再试一次。无痕默认禁用扩展，能打开就说明是广告拦截类扩展把长连接拦了——电报网页版靠 WebSocket 保持在线，这类扩展经常把它当广告请求处理。

## 五、几个真实会撞上的提示，各自怎么处理

**二维码过期（QR code expired）。** 有效期通常半分钟到一分钟，页面自己会刷新。别去点浏览器的刷新按钮，那是整页重载，反而更慢。

**提示尝试次数过多（Too many attempts, please try again later）。** 短时间内反复扫码、反复请求验证码触发的限流。这时候继续试只会把冷却时间越拉越长，停手，隔一段时间再来。

**手机端死活不弹确认。** 两个方向查：手机系统层面是不是把 Telegram 的后台进程杀了（省电管家、电池优化那一类工具最爱干这事）；账号层面是不是开了「新设备登录需要确认」之类的额外限制。

**扫完码进去了，但界面空白、消息一直转圈。** 到这一步登录已经成功，问题在资源加载和长连接上，跟授权没关系。先 `Ctrl + F5` 强制重载，再排扩展和线路。这类按症状分层的排查入口在 [电报网页版中文指南](https://tlgrpv-web.com) 里按浏览器分开列过。

## 六、迁移完顺手做掉的三件事

**设备清单定期清一遍。** 列表里躺着一台 2019 年的 Windows 7，那不是纪念品。每季度看一次，不认识的当场终止。

**公用电脑用无痕窗口，用完点退出。** 关标签页不等于退出登录，Cookie 还在，人走了账号还挂着。无痕窗口关掉即清，也不用麻烦号主重扫。

**新设备登录提醒开着。** 手机端「设置 → 隐私与安全」里把登录提醒保持开启。别人在别处扫了你的码，你手机第一时间就会弹出来——这是唯一一个能在事后立刻发现问题的机制。

再顺一句浏览器那边的账：密码管理器里存着几十个站点的密码，那套东西跟着账号走；电报网页版不在这套体系里，它靠设备列表。两套账分开记，就不会再有"为什么只有它要重登"的困惑。各浏览器的会话与权限差异、换设备前后的检查清单，可参考 [tlgrpv-web.com 的浏览器登录部分](https://tlgrpv-web.com)。

## 七、换个说法记住这件事

**换浏览器不是换皮肤，是换设备。**

带得走的是你自己存的书签、记得住的域名、以及手机端那条一直活着的会话；带不走的是浏览器里那份授权密钥——它属于具体某台机器上的某个浏览器配置文件，本来就不该跟着你跑。

所以下次换电脑，看到别的站都还登着、只有电报弹二维码，不用怀疑机器坏了。照上面五步走一遍，两分钟的事。真正值得花时间的是那三件收尾：清一遍设备列表、公用电脑改成无痕、登录提醒打开。做完这三件，你在哪台机器上登、什么时候被登，心里都有数。
