# 一台Firefox并排开两个Telegram网页版账号：容器标签9步配置＋7项隔离验证

想同时开两个号，又不装第二个浏览器。这是我上个月最实在的诉求：一个号挂着客户群，一个号只看频道，两边都得常开，来回退登再扫码的体验撑不过两天。Chrome 那边我用无痕窗口顶过一阵，代价是窗口一关就清干净，第二天从头扫一遍码，扫到烦。Firefox 的容器标签刚好卡在这个需求上——同一套浏览器、同一个窗口、两套互不认识的会话，关掉浏览器下次打开还在。下面是我实际配的过程：先把设置路径走一遍，再把隔离效果逐项测一遍，测不过的地方也一并写清楚。容器概念的入门说明在 [Telegram网页版中文指南](https://tlgrgs-web.com) 里占了独立一节，界面截图可以对着核。

## 第二个号一登，第一个就掉线，账是记在域名上的

Telegram 网页版把登录态放在这个域名下的 Cookie 和本地存储里，浏览器按域名分账，一个域名就一本账。第二个号登进去，写的是同一个位置，第一个号的会话被覆盖，点一下刷新已经变成新号了。无痕窗口能临时借一套独立存储，但它不落盘，关窗即弃，还得重新扫码。

容器标签给的是第三种东西：同一个域名，按容器分别记 Cookie、localStorage、IndexedDB 和缓存，互不覆盖，而且是持久保存的。你要做的只是告诉浏览器"这个标签属于哪个容器"。

## 装扩展：三步把容器界面拿到手

容器功能的内核在浏览器里（对应 `privacy.userContext.enabled` 这个开关），但"新建容器、管理容器"这套界面是扩展提供的，装不上就没有入口。

1. 地址栏敲 `about:addons` 回车，左侧点"扩展"。
2. 右上角搜索框输入 Multi-Account Containers，挑作者一栏写着 Mozilla 的那个。
3. 点"添加到 Firefox"，弹窗里权限写的是"访问您在所有网站的数据"，点"添加"。

装完图标多半不在工具栏上。点地址栏右侧的拼图图标，找到它，点右边的齿轮选"固定到工具栏"。Firefox 109 之后所有扩展都收进这个拼图里，100 以前的版本是直接摆在工具栏上的——很多人说"装完找不到图标"，卡的就是这处版本差异。

## 给每个号建一个容器，钉死在同一个域名上

这一步配好，后面就不用每次手动挑容器了。

1. 点工具栏的容器图标 → "管理容器" → "新建容器"。
2. 名称写"工作号"，颜色选蓝；再来一个"私人号"，选绿。颜色不是装饰，两个标签页并排时靠标签顶部那道颜色条区分，比看标题快得多。
3. 在容器编辑面板里勾上"限制到指定站点"（Limit to designated sites），把这个网页版的域名填进去。勾选后凡是从该域名点开的链接都自动落在这个容器里，不会手滑开成默认容器——整套配置里最省事的就是这一下。
4. 打开第二个号：右键任意标签页 → "新建容器标签页" → 选"私人号"；已经有页面的，右键标签 → "重新打开于新容器" → 挑另一个容器，页面会带着当前地址在新容器里重载。

顺手提醒一句，容器名字里别写"大号""小号""备用"，写用途。工具栏图标、右键菜单、存储面板的下拉里都会显示这个名字，写用途才有辨识度。

## 容器、无痕窗口、独立配置文件，选哪个

| 方案 | 会话是否隔离 | 关浏览器后是否保留 | 能否两个号同屏 | 主要代价 |
| --- | --- | --- | --- | --- |
| **容器标签** | 是，按容器分账 | 保留 | 能，同一窗口并排 | 扩展共用、密码库共用 |
| **无痕窗口** | 是 | 不保留，关窗即清 | 能 | 每次重新扫码 |
| **独立配置文件**（`about:profiles`） | 是，连书签扩展全分开 | 保留 | 不能，得开两个实例 | 两套配置各自维护 |
| **装第二个浏览器** | 是 | 保留 | 能 | 多占一份内存，多一处要更新 |

我的选择是容器：代价最小，缺点集中在"扩展和密码库不隔离"，而这两样对同时开两个号影响不大。

## 隔离验证：七项依次测，别凭感觉

配完不要急着信。按下面顺序测，每项都有能看见的判定依据。

1. **互不挤占**。A 容器里登账号甲，B 容器里登账号乙，两个标签并排放着，各发一条消息，看头像、用户名、已读回执对不对得上。
2. **反向登出**。在 A 里点头像 → 退出登录，切到 B 刷新。B 还在线才算隔离成立；B 跟着掉了，说明两个标签落进了同一个容器——看标签颜色条是不是同一个颜色就知道。
3. **存储层核对**。按 F12 → "存储"面板 → 左上角那个原本显示"默认"的下拉，切到"工作号"，看 Cookie 列表；再切"私人号"，同一个域名下两套 Cookie 的值不同。这一条是硬证据，比看页面靠谱。
4. **localStorage 与 IndexedDB**。同一面板里切到"本地存储"和"IndexedDB"，两个容器的记录条数与键名各自独立，不会出现"甲号的缓存键出现在乙号容器里"。
5. **权限分开记**。在 A 里允许桌面通知，回到 B 看，B 那边应该还是"询问"。验证位置：设置 → 隐私与安全 → 权限 → 通知 → 设置，同一个域名会出现两条记录，分属两个容器。
6. **缓存各清各的**。设置 → 隐私与安全 → Cookie 和网站数据 → 管理数据，搜域名；只清 A 的缓存，B 刷新后界面不该掉登录。这一步做对了，以后修显示问题就不用担心把另一个号清掉。
7. **重启后复查**。完全退出 Firefox 再开，两个容器的号都还在、且还是各自的号。容器是持久的，这是它跟无痕窗口最根本的差别。

| 验证没通过时的现象 | 最可能的原因 | 处理 |
| --- | --- | --- |
| 两个标签颜色条一样 | 打开时没选容器，落在了默认容器 | 右键标签 → "重新打开于新容器" |
| 右键菜单里没有"新建容器标签页" | 容器菜单被关掉了 | `about:config` 里把 `privacy.userContext.enabled` 改回 `true`，重启 |
| 私有窗口里找不到容器选项 | 无痕模式不支持容器 | 用普通窗口，或改用独立配置文件 |
| 换电脑后容器全没了 | 容器名与登录状态都不同步 | 在新机器上重建容器后重新扫码 |

## 容器管不了的三件事

把边界说清楚，能省掉一堆无谓的折腾。

**一个手机号只有一个账号。** 容器解决"同一台电脑上并排"，不解决"多出一个号"。它分的是浏览器里的账，不是账号本身。

**密码管理器不按容器分。** 同一个域名只存一条登录信息，两边都点"保存密码"会互相覆盖，A 里很可能被自动填成 B 的号。两个号都手动输，或者干脆把自动填充关掉，比事后找密码省事。

**网络身份不隔离。** 两个容器走同一条出口、同一台机器，下载目录、书签、扩展规则也是共用一份。群文件照样往同一个"下载"文件夹扔，扩展的拦截规则也是同一套。

另外有两处提示文案顺手记下来：装扩展时如果弹出"此扩展无法安装，因为它似乎已损坏"，通常是安装包在路上被中间设备改过，换个网络重装即可；容器编辑面板里如果"限制到指定站点"勾了却仍从默认容器打开，检查一下填的域名是否带上了子域前缀，规则是逐条匹配的。想核对某一步的界面长什么样，[浏览器与多设备相关的图文目录](https://tlgrgs-web.com) 里分节列着。

## 把这套配置用成习惯

**颜色固定下来。** 蓝的永远是客户群，绿的永远是频道，不要今天换明天换——换过一次之后，你会在错误的容器里发消息，而且事后很难发现。

**新设备先建容器再登录。** 别在默认容器里先登一个号，再"重新打开于新容器"搬过去，搬的过程中 Cookie 容易带乱，得不偿失。

**隔段时间回"管理容器"看一眼。** 有些站点会诱导创建新容器，列表里慢慢就多出一串没名字的。删掉多余的，只留你认得的那两三个。

这套配置我在两台机器上跑了快两个月：同一窗口里两套会话，互不干扰，关掉浏览器第二天打开还在原位。回到最初那个诉求——想同时开两个号，又不装第二个浏览器，容器标签是目前最省力的答案。剩下要把账号、协作、文件这些环节理顺，可以从 [tlgrgs-web.com](https://tlgrgs-web.com) 的目录按章节往下看。
