# 公司网里只有网页版在转圈：换过 7 条线路才发现，卡它的是代理、白名单和一张自签证书

周一早上九点四十，客户在群里丢了三个文件，说十点半前确认。我在工位上打开浏览器：公司邮箱秒开，会议室预订系统秒开，连楼下咖啡店的外卖页都在加载缩略图。只有那个网页版——地址栏转了两圈，页面停在灰白底上，中间一个小圈一直在转，转到我把咖啡喝完它还在转。

我先怀疑网速，测了一遍下行，两百多兆。又怀疑对方站点挂了，掏出手机切到流量，同一页，两秒出来。那一刻我才承认：公司网没坏，它只是对这一个站点关着门。接下来一周我换了七条线路、试了四个浏览器，才把门后面那三把锁分清。

## 一、先做一个两分钟的对照实验，别在工位上瞎猜

判定责任归属，只需要一台手机：

1. 手机关掉 Wi-Fi，用移动数据打开同一个页面；
2. 手机能开、电脑不能开，问题在公司这一侧；
3. 两边都打不开，先别骂网管，去看浏览器缓存和系统时间；
4. 两边都能开、只有电脑慢，是代理在中间做逐条转发。

这个对照会省掉后面所有扯皮。我拿它试了三次，结论稳定：手机一直能开，公司电脑一直转圈。

## 二、同样一句"打不开"，六种环境六种死法

| 网络环境 | 屏幕上看到的现象 | 真正卡住的东西 | 一眼辨认的办法 |
| --- | --- | --- | --- |
| 家里宽带直连 | 能开，偶尔加载慢 | 出口线路质量 | 换个时段再试，或换线路 |
| 公司直连（无代理） | 白屏停顿十几秒，才报 `ERR_CONNECTION_RESET` | 出口防火墙按域名丢包 | 开热点立刻能通，就是它 |
| 公司 PAC / 代理 | 地址栏一直显示"正在等待代理隧道"，报 `ERR_TUNNEL_CONNECTION_FAILED` | 代理不转发 443 的 CONNECT | 去看系统代理设置里勾了什么 |
| 公司 SSL 解密 | 能连上，但弹"你的连接不是私密连接"，`ERR_CERT_AUTHORITY_INVALID` | 中间人换了一张内网 CA 签的证书 | 点开证书看"颁发者"是谁 |
| 手机热点 | 页面能开，扫码后卡在"正在连接" | 运营商 NAT、出口 IP 被大量共用 | 只看登录那一步是否走完 |
| 公司 VDI / 远程桌面 | 全白，连站点图标都不加载 | 服务器侧出网策略 | 换回本机立刻正常 |

中文的分步核对可以对着 [浏览器登录前检查清单](https://tlgroq-web.com) 一条条过，它把访问入口、浏览器版本和网络状态拆成了独立条目，比在工位上猜快得多。

## 三、代理这一层，路径比你想的深

Windows 上有两个地方能设代理，而且经常只有一个生效。新版设置里是「设置 → 网络和 Internet → 代理 → 手动设置代理」，地址一栏填 `PROXY_HOST:8080`，下面还有个"请勿对本地地址使用代理服务器"的勾。老控制面板里是另一套：`Win + R` 输入 `inetcpl.cpl`，进「连接 → 局域网设置」，那里可能勾着"使用自动配置脚本"，指向一个 `http://pac.corp.local/proxy.pac` 之类的地址。

这个差别很要命。Chrome 和 Edge 自己不管代理，直接读系统设置，`chrome://settings/system` 里那个"打开您计算机的代理设置"就是跳去上面两处的按钮。Firefox 有自己的一套：「设置 → 常规 → 网络设置 → 设置」，默认是"使用系统代理设置"，但企业镜像经常把它改成手动填死的老代理地址——那台代理早下线了，页面就永远转圈。

两条报错文案要分清：`ERR_PROXY_CONNECTION_FAILED` 是本机连不上代理本身，`ERR_TUNNEL_CONNECTION_FAILED` 是代理收下了请求但拒绝建立隧道。前者是地址写错，后者是策略不让走。

命令行能自证。Windows 10 1809 之后系统自带 `curl.exe`，在 PowerShell 里跑：

```
curl.exe -v --proxy http://PROXY_HOST:8080 https://tlgroq-web.com
```

回显里看两行：`CONNECT tlgroq-web.com:443` 有没有发出去，后面跟的是 `200 Connection established` 还是 `403`。403 就说明不是网络不通，是代理明确拒了。

还有一种情况改不动：公司用组策略强推。地址栏进 `chrome://policy`，搜 `ProxyMode`，如果它标着"平台政策"，这值就是 IT 下发的，界面上那几栏是灰的，点了也不保存。这时候别硬刚配置，走后面的绕过思路。

## 四、白名单放行了主页，不等于放行了它要的东西

公司白名单一般按"域名 + 端口"写，常见的只开 80 和 443。主页域名进了名单，页面确实能打开，但二维码区域一直是空框——那是静态资源在另一个子域上，没进名单。

另外几种典型：

- `ERR_NAME_NOT_RESOLVED`：内网 DNS 只解析白名单域名，域名压根没解析出去；
- `net::ERR_HTTP2_PROTOCOL_ERROR`：设备只放 HTTP/1.1，把 HTTP/2 的帧丢了；
- 页面加载到 80% 就停住、控制台一串请求 pending：长连接被掐，wss 走不出去。

跟 IT 沟通别只说"把电报放开"，把三样东西给全：要访问的域名清单、端口 443、用途一句话。清单越具体，批得越快。

## 五、证书中间人：它在换证书，不是在偷看你

公司出口常挂一台 SSL 解密设备，用自己的 CA 把证书重签一遍，再发给浏览器。于是页面上冒出"你的连接不是私密连接"，代码 `ERR_CERT_AUTHORITY_INVALID`。

看证书就能确认。Chrome 117 之后地址栏那个小锁换成了一个调节滑块的图标，点它 → "连接已加密" → "证书有效"，进去看"颁发者"一栏；正常是公共 CA 的名字，被解密过的会是一个内网命名，比如 `Corp-IT-SSL-Inspection-CA`。

最能说明问题的是浏览器之间的反差：**同一台机器，Chrome 能开、Firefox 报证书错。** 原因是 Chrome 和 Edge 读 Windows 证书存储，IT 推了根证书它们就认；Firefox 用的是自己那套 NSS 证书库，默认不读系统存储。修法是在 Firefox 地址栏进 `about:config`，把 `security.enterprise_roots.enabled` 设为 `true` 再重启；或者走「设置 → 隐私与安全 → 证书 → 查看证书 → 导入」，手动把那张根证书塞进去。

那条红色警告页上的"继续前往"，别点。在公司网里点下去，等于你主动放弃了这一层的校验，后面扫的码、登录的会话都在明文通道里跑。

各浏览器的权限、缓存和代理行为差异，[Chrome 浏览器使用建议与 Edge 浏览器使用建议](https://tlgroq-web.com) 是分两篇写的，对照着看能省不少试错。

## 六、绕过思路，按代价从小到大排

1. **先定性**：手机流量交叉验证，确认是公司这一侧的问题，别把时间花在清缓存上。
2. **申请例外**：把域名清单、端口、用途交给 IT，写成工单。这是唯一能长期用的路。
3. **自建出口**：手机开热点，或者用 USB 共享网络。代价最低、最不惹事，适合临时传个文件。
4. **加代理例外列表**：`inetcpl.cpl` → 连接 → 局域网设置 → 高级 → 例外，把域名和通配符填进去。PAC 脚本环境里这一栏是灰的，改不了，回到第 3 条。
5. **换浏览器做判别**：Chrome 通、Firefox 不通，是证书；两个都不通，是网络。
6. **网页版走不通就用客户端**：但别在 VDI 里装，客户端缓存会卡在漫游配置上，每次登录都像重装。
7. **把能用的组合记下来**：哪个网络 + 哪个浏览器 + 什么版本，写进备忘录。下次换工位、换会议室，不用第七次重来。

## 七、网络不归你管的时候，选对入口比会调参数值钱

公司网能开别的网站，从来不是"电报能用"的证据。它只能证明出口是通的，证明不了代理愿意转发隧道、证明不了白名单里那个域名在列、更证明不了中间那台设备没换证书。把这三件事分开看，转圈的页面就从"玄学"变成了三个可以逐一排除的开关，而这三个开关里，至少有两个不在你手上。

我后来的固定做法是：进会议室之前先用手机会话把要用的东西看好，公司电脑只做确认和回复；真要传文件，热点开一次，两分钟结束。顺手把退出流程走完整——公用机器上用完不退，比打不开更麻烦，站点上 Cookie 与登录状态那篇把会话、退出、共享电脑三种情况分得很清。

还有一层经验：在 [tlgroq-web.com](https://tlgroq-web.com) 这类中文指南站上，浏览器版本、缓存、通知、下载位置是分开成篇的。卡住的时候按现象挑一篇看，比从头翻一遍快，也比在工位上反复按 F5 快。
